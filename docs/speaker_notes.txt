We will begin with the energy problem and why the choice of hardware matters. Then we will

Slide 3  Problem [0:20-1:30]

The main motivation is that artificial neural networks (ANNs) need more resources as they
become larger. Running them requires computation and electricity, and the hardware also needs
cooling. This motivates exploring other ways to process information efficiently.

Spiking neural networks (SNNs) are inspired by how biological neurons communicate. Instead of
passing real-valued activations, neurons send discrete events called spikes. When activity is
sparse, suitable hardware may perform less arithmetic and move less information.

That gives us the question behind this project: can a spiking network approach the image-
classification accuracy of a convolutional neural network (CNN) while using fewer resources? We
keep the dataset and overall network structure consistent so that the change in processing is
the main comparison. Accuracy and energy must be considered together, because saving energy
matters only if the model still performs the task well.


Slide 4 Part 1  Conventional hardware [1:30-2:30]

This slide shows a simplified view of central processing unit (CPU) and graphics processing
unit (GPU) hardware. Model weights and intermediate values are stored in memory, then brought
to the processor for calculation. Moving that data consumes energy, so both computation and
communication contribute to cost.

A key point is that sparse neural activity does not automatically turn into savings on this
hardware. Our PyTorch implementation uses dense tensor operations, so many zero inputs still
participate in the computation. The spiking neural network also repeats processing over several
time steps for each image.

This is why we measure actual performance. The hardware determines how much of the potential
sparsity advantage becomes a real benefit.


Slide 5  Dataset and preprocessing [2:30-3:40]

CIFAR-10 takes its name from the Canadian Institute for Advanced Research, with ten referring
to the image classes. This dataset gives both models sixty thousand small color images,
including cars, airplanes and animals. The standard split uses fifty thousand images for
training and ten thousand for testing.

Before training, we convert the images into tensors and normalize each color channel. We also
use random crops, horizontal flips, color jitter and small rotations to create variation in the
training examples.

The purpose of augmentation is to help a model recognize the important visual features even
when an image looks slightly different. For example, an object should remain recognizable after
a small rotation or a change in color.

Both models receive the same preprocessing. Consistent data conditions make it easier to
compare how the models work.


Slide 6  Model architecture [3:40-4:50]

The convolutional neural network (CNN) and spiking neural network (SNN) share the same compact
convolutional structure. Convolutional layers learn visual patterns, pooling reduces the size
of the feature maps, and the classifier produces a prediction for one of the ten classes.
Keeping the overall structure and capacity similar makes the comparison more controlled.

The difference is how activity moves through the network. The conventional network uses
conventional activations and processes each image in one forward pass. The spiking network uses
spiking neurons that accumulate input and communicate through spikes.

The spiking network also uses temporal effective batch normalization (TEBN), to help normalize
activity across time. It receives the same image over four time steps and averages the outputs
to make its prediction. The extra temporal processing is one reason we compare speed and energy
alongside classification accuracy. Similar parameter counts therefore do not imply the same
amount of computation.


Slide 10  Changes and enhancements [4:50-6:00]

Our implementation is a simplified reproduction of the paper's method. We use a smaller network
and a thirty-epoch training budget to make the experiments manageable with the available
computing resources. Both models use the same optimizer and learning-rate schedule so that the
training setup remains consistent.

We also examine more than the final accuracy. Runtime, memory use, graphics processing unit
(GPU) utilization and power help describe the practical cost of running each model. Firing
rates show how active the spiking network is, while operation counts support a separate
theoretical energy estimate.

It is important to keep those estimates separate from the measurements. An operation-based
estimate describes potential arithmetic costs under specific assumptions. It does not
demonstrate that the model has been deployed on a neuromorphic chip or that the same savings
will appear in a complete hardware system. A complete hardware result would also depend on data
movement and other overheads.
